2026-07-16 — docker_container / docker_network adopt on create

  • The docker provider’s create path now adopts a container or network of the same name that already exists on the host (one that predates stratum management) instead of colliding on the name or recreating it. On create, stratum docker inspects first: not found → create as before; found and every declared attr matches the live object → ADOPT (mutate nothing, record the live id into state, next plan is a no-op — [docker] ADOPT existing container <name> ... — no change); found but a declared attr conflicts → hard error listing each differing attr (declared vs live) and the options (edit the .strat, remove the live object by hand, or apply -r). Stratum never rm -fs on the adopt path — that recreate would be the outage this avoids. Only declared attrs are checked, each as a subset/equality, so undeclared live details (image-baked env, the default bridge network, daemon labels, extra ports) don’t block adoption. Gated attrs: container image / restart / networks / labels / env / ports / volumes (rules in providers/docker.md), network driver. pull / env_file / memory / memory_swap / command / healthcheck aren’t observable-or-comparable reliably from inspect and are adopted on trust (documented). Update behavior is unchanged (recreate). Mirrors the cloudflare_dns_record create-is-upsert idempotency. Lets a live box with a hand-run Caddy + a pre-existing stratum-edge network be brought under management with no downtime.

2026-07-15 — system_ufw declarative firewall + forward-compatible state guard (#138, #139, #140)

  • New system_ufw kind (system provider) owns a host’s firewall enable state declaratively (system_ufw { enabled = true }; apply = ufw --force enable, delete = ufw --force disable, both idempotent), replacing the raw ssh_exec "ufw --force enable" escape hatch. It ships with a two-layer anti-lockout guard. Layer 1 (#139): Registry::validate_desired makes control-plane lockout impossible to express — any host that enables ufw must also declare a system_ufw_rule allowing that host’s SSH control port (from the injected _ssh_port meta attr, default 22) and must not deny it, catching both lockout paths (default-deny with no allow rule, or deleting the allow rule) at plan time. Layer 2 (#140): the enable is wrapped in a dead-man’s switch — arm a transient stratum-deadman systemd timer (systemd-run --on-active=<deadman_secs>s … ufw --force disable), enable, verify reachability on a brand-new SSH connection (ControlMaster=no/ControlPath=none so it never joins the possibly-dead master), then cancel on reconnect, or let the timer fire and auto-restore access, marking the step FAILED. New deadman_secs attr (default 120; 0 opts out), echoed into state so the one-sided diff doesn’t flag perpetual drift.
  • Forward-compatible state guard (#138): State::load now hard-errors when a state.json’s version exceeds STATE_VERSION (the highest schema version this build understands), instead of silently misreading — and corrupting on save — a file written by a newer stratum. Covers both split files via load_merged.

2026-07-15 — cloudflare_dns_record is idempotent (#137)

  • cloudflare_dns_record create is now an upsert instead of a blind POST. It first looks up existing records (GET /zones/<id>/dns_records?type=&name=) and: adopts an identical existing record (same content/ttl/proxied) by recording its Cloudflare id into state and writing nothing — fixing HTTP 400 "An identical record already exists" (81058); converges a sole record of the same type+name that differs, in place via PUT; and only creates (POST) when the name is genuinely free (or several round-robin records exist and none matches). Lets ingress deploys manage a record already present in Cloudflare (threshold’s memory.kbach.dev) as a no-op. Mirrors the caddy_route adopt-by-id idempotency.

2026-07-14 — host addr can reference a var (#109)

  • A host body may now reference var.<name> (bare or "${var.<name>}"), so a host address can come from the environment: var "box_host" { from_env = "CLAUDE_BOX_HOST" } then host "box" { addr = var.box_host }. Implemented by collecting var blocks before hosts (new pass 0.5) instead of after — vars are literal-only leaves, so they have no dependency on hosts/secrets and reordering is safe. Host bodies are evaluated against a vars-only scope: var.x resolves while secret.x, another host, a resource ref, or input.x inside a host block still hard-fail as references not allowed inside host blocks (hosts gain no access to secrets or other hosts). Part of the app-deploy steward RFC (#131). Documented in language/hosts.md (Literal-only, except var), language/references.md, and language/overview.md (evaluation order now vars → hosts → secrets → namespaces → resources).

2026-07-01 — ssh_keypair (#74)

  • New ssh_keypair kind in the SSH provider: generates a local ed25519 keypair (no host, a HOSTLESS_KIND). Only attr is path (optional, force_new; default ~/.stratum/keys/<name>, stored unexpanded for portability). The private half is written mode-0600 (unix; ACL-scoped under the user profile on Windows) plus a .pub sidecar; state carries only { path, public_key, fingerprint, sha256 } — the private key material never persists (the system_secret_file secret-in-state contract, reversed). Re-apply reuses an existing valid key (never clobbers a public key already authorized on live boxes); plan --refresh flags a missing/swapped key as drift; delete removes the local private key + sidecar, leaving the deployed public half. Powers the ephemeral per-box deploy-key flow: public key → do_droplet.user_data cloud-init ssh_authorized_keys (pending-ref defers the droplet), private key → the host’s identity_file. Documented in providers/ssh.md (kind section + deploy-key example + trace lines), providers/index.md (read table); regenerated generated/provider-kinds.md (now 20 kinds).

2026-07-01 — stratum ssh (#73)

  • New stratum ssh <host> [-- cmd...]: open an interactive shell (or run a one-off command) on a managed host, reusing the connection settings stratum already knows — the host block’s addr (resolved from state for from_resource hosts), its identity_file/port/jump_host, and any pinned host_key (verified with StrictHostKeyChecking=yes). Unlike the automation path it drops BatchMode (a human may need to answer a prompt), allocates a TTY for the shell case, and execs ssh so it exits with ssh’s code (scriptable). A <HOST> matching no declared block is treated as a raw user@addr. Refactored ssh_args: host_key_flags(host) (the pin decision) and SshTarget::conn_flags() (-i/-p/-J) are now shared between base_flags and the interactive path. Live-verified against a real sshd (pinned host connects; a wrong pin → “Host key verification failed”). Documented in cli.md § ssh.

2026-07-01 — do_droplet cloud-init user_data (#70)

  • do_droplet gains user_data (cloud-init config run at first boot) and user_data_file (a local file path inlined into user_data at config load — preferred, since .strat strings can’t hold raw newlines). user_data is force_new (cloud-init runs once, so a change recreates the box) and echoed into state so an unchanged config re-plans as a no-op; the DO API never returns it, so it isn’t drift-observed. user_data/user_data_file are mutually exclusive (UserDataConflict). Unblocks ephemeral per-box deploy keys and cloud-init host-key injection (the zero-friction end of host-key pinning). Documented in providers/digitalocean.md (attr table + cloud-init section); regenerated generated/provider-kinds.md.

2026-07-01 — do_ssh_key (#69)

  • New do_ssh_key kind (DigitalOcean provider): imports an SSH public key into the DO account via POST /v2/account/keys, so do_droplet.ssh_keys can reference do_ssh_key.<n>.fingerprint instead of requiring a key pre-imported by hand. Removes the last manual pre-step for a from-scratch DO deploy. public_key is force_new (rotation = delete + re-import, cascades to referencing droplets); key_name (defaults to resource name) is rename-only. read → Present { token, public_key, key_name, id, fingerprint } / Absent / Unknown (redacted token). Hostless (API, never SSH). Documented in providers/digitalocean.md § do_ssh_key + providers/index.md read table; regenerated generated/provider-kinds.md (19 kinds).

2026-07-01 — host-key pinning (#67)

  • host block gains a host_key field: pin the box’s SSH host key and stratum uses StrictHostKeyChecking=yes against a stratum-managed ~/.stratum/known_hosts, verifying the key instead of the default trust-on-first-use (accept-new). Closes the MITM window on first contact with a fresh box. Unset → prior accept-new behavior, unchanged (purely additive). Accepts raw key material or a full ssh-keyscan line. Fail-closed: an unwritable/missing known_hosts makes ssh refuse rather than trust. Wired through a process-global pin registry so both SshTarget::pre_args and the base_args call sites (docker/git) verify a pinned host. Documented in language/hosts.md § host_key. Live-verified against a real sshd (correct pin authenticates through; wrong pin → “Host key verification failed”).

  • New cloudflare provider (crates/providers/cloudflare) with one kind, cloudflare_dns_record: A/AAAA/CNAME records in a Cloudflare-managed zone via the Cloudflare API v4 (no SDK, same reqwest/429-backoff style as do_droplet). So a deploy can end at a real HTTPS domain — pair it with a do_droplet for the box and a web server for auto-TLS. Verified end-to-end live: droplet → cloudflare_dns_record → Caddy served https://<domain> with a real Let’s Encrypt cert, then a clean destroy removed the record and the box.

  • Attrs: token (secret, Zone.DNS:Edit, redacted in state), zone (name, resolved to id) or zone_id (both force_new), type, name (relative → FQDN; @/empty = apex), value, ttl (default 1 = auto), proxied (default false / DNS-only so origin ACME works). read reports Present { type, value, ttl, proxied, record_id, fqdn } or Absent; value/ttl/proxied are read live for drift, identity carried from state. New providers/cloudflare.md, added to providers/index.md (kind + read tables) and SUMMARY.md. cloudflare_dns_record is a HOSTLESS_KIND (API, never SSH).

  • state rm: drop resource(s) from a state file without touching any host — a recovery tool for out-of-band deletions and wedged teardowns. Positional <addr> for one resource, --host <addr> to forget every resource on a gone host, -p/--path, -y/--yes (preview without it). Documented in cli.md § state rm and added to the command summary.

  • destroy --skip-unreachable: pre-probe each SSH host and drop the deletes for any that don’t answer (they die with the host), so a doomed host’s ssh timeouts don’t strand the do_droplet delete. Skipped resources are removed from state. Documented in cli.md destroy flag table.

  • -t/--target on plan and apply: restrict the run to <kind>.<name> plus its depends_on closure, dropping everything else (including unrelated Deletes; the destroy guard still applies). Mirrors Terraform -target.

  • -r/--replace on plan and apply: force a recreate of a resource whose attrs match state; cascades through depends_on. Also the opt-in for an in-place change to a create-time-immutable (force_new) field.

  • --check-after on apply: the post-apply self-check is now opt-in, not automatic. Off by default — it costs one ssh round-trip per resource. Updated cli.md, architecture.md (flow step 12), introduction.md, and the bootstrap-droplet / book-serve tutorials, which previously showed self-check output from a plain apply.

  • Parallel apply / --max-parallel (default 4): independent steps run concurrently; chained steps serialize, capped under sshd MaxStartups. bootstrap-droplet.md now ships depends_on edges so the apt/ufw chain stays safe under the parallel default, and its “depends-on graph is not implemented” claim is removed (topo sort is implemented).

  • Action::Replace (symbol ±) + PlanSummary.replace: documented in architecture.md and the cli.md plan symbol/summary tables.

2026-06-11 — apply locking (#2)

  • apply and destroy now hold an exclusive OS file lock (File::try_lock on <state>.lock) for the whole invocation; a concurrent run against the same state file errors immediately, naming the holder (pid + age where the platform allows reading it — Windows’ mandatory lock blocks that, and the error degrades to a generic live-holder line). Killed processes release the lock automatically — no stale-lock cleanup exists or is needed. Namespace mode locks _shared.json as well. plan stays lock-free. Documented in cli.md § Locking. Verified with two concurrent real-binary applies.
