stratum

Hosts

A host block names a managed box — reached over SSH by default, or over the stratum agent. Other blocks reference its fields via host.<name>.<field>.

host "prod" {
  addr = "root@192.0.2.10"
  port = 22
}

host_block ::= "host" string "{" attr* "}"

The single label is the host’s name and must be unique within the document. The body is a flat list of attributes; nested blocks are allowed but rare in practice.

Literal-only, except var

Host bodies are literal with one exception: they may reference a var. Vars are collected before hosts, so a host addr (or any other host field) can pull an environment-driven value:

var "box_host" { from_env = "STRATUM_BOX_HOST" default = "root@192.0.2.10" }

host "box" {
  addr = var.box_host        # ok: vars resolve before hosts
  # addr = "${var.box_host}" # the interpolated form works identically
}

Nothing else is in scope. A host body cannot reference another host, a secret, a resource, or an input — those still error with references not allowed inside host blocks:

host "prod" {
  addr = host.staging.addr   # error: no host/secret/resource refs in a host body
}

State-backed hosts: from_resource

A host whose box is provisioned by stratum itself (e.g. a do_droplet) can take its addr from that resource’s state instead of a literal:

resource "do_droplet" "portal-box" {
  token    = secret.do_token.value
  region   = "sgp1"
  size     = "s-1vcpu-1gb"
  image    = "ubuntu-24-04-x64"
  ssh_keys = ["my-key"]
}

host "portal-box" {
  from_resource = "do_droplet.portal-box"   # addr = that resource's state `ssh_host`
  # addr_attr = "ip_address"                # optional, default "ssh_host"
}

This is a declarative source (like secret { from_env }), not a ref — hosts stay literal-only leaves. The division of labor: resources read another resource’s state attrs directly via resource references (do_droplet.web.ip_address); hosts can’t hold refs, so from_resource is their one state-reading construct. Resolution happens at load time, from the state file:

  • Source resource in state → host.X.addr is its ssh_host attr; everything behaves as if you’d written the literal.
  • Not in state yet → the host is pending: every resource targeting it is deferred (excluded from the plan, with an explicit deferred (host pending: ...) section), including stratum’s implicit _stratum_* tuning resources. Nothing is keyed, diffed, or executed against a host that doesn’t exist.

stratum apply converges automatically: if a pending host’s source resource lands in state during the round (the droplet was just created), apply runs one more round so the deferred resources apply in the same invocation — bare cloud account to bootstrapped box, one command. The loop is bounded to one extra round; chains of boxes provisioning boxes are out of scope. plan never loops — it shows round one plus the deferred section.

Declaring both addr and from_resource is an error.

Fields

There is no schema for host fields — anything you put in a host body is accessible by ref. The conventional fields are:

fieldtypenotes
addrstringuser@host form. Passed to the ssh binary as the destination.
userstringSSH user. Prepended as user@ only when addr doesn’t already carry one.
portnumber|stringSSH port. Lowered to -p <port>.
identity_filestringPrivate key path. Lowered to -i <path> -o IdentitiesOnly=yes (agent keys suppressed).
jump_hoststringBastion. Lowered to -J <jump_host>.
host_keystringPin the box’s SSH host key (verify instead of trust-on-first-use). See below.
swapstring|number|boolControls the per-host implicit swapfile resource. See below.
transportstring"ssh" (default) or "agent". Selects how stratum reaches the box. See below.
agent_urlstringAgent base URL (e.g. https://192.0.2.10). Required when transport = "agent".
agent_tokenstringName of the environment variable holding the agent bearer token. Required when transport = "agent".
agent_cert_sha256stringOptional hex sha256 of the agent’s TLS certificate, to pin a self-signed / tls internal cert.

The connection fields (user, port, identity_file, jump_host, host_key) are wired through: the config loader lowers them to reserved _ssh_* attrs that every SSH-based provider reads when building its ssh invocation (see SshTarget). They compose with — and override the corresponding options from — your ~/.ssh/config and ssh-agent.

host_key

By default stratum connects with StrictHostKeyChecking=accept-new — trust-on-first-use: it accepts whatever host key the box first presents. That leaves a MITM window on the very first connection to a fresh box. Set host_key to the box’s public host key and stratum verifies it instead:

host "box" {
  addr     = "root@1.2.3.4"
  host_key = "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA..."
}
  • When set, every ssh call to that host uses StrictHostKeyChecking=yes against a stratum-managed known_hosts file (~/.stratum/known_hosts). A key mismatch (rebuilt box, MITM) hard-fails the connection instead of silently re-trusting.
  • The value is either raw key material (ssh-ed25519 AAAA...) or a full ssh-keyscan line (the leading host token is stripped for you).
  • Fail-closed: if the known_hosts file can’t be written, ssh refuses the connection rather than falling back to trust.
  • Unset → the prior accept-new behavior, unchanged.

Where to get the key: bake it into a custom image, read it from the cloud provider’s console, or capture it once with ssh-keyscan -t ed25519 <ip> (itself trust-on-first-use, but you pin it thereafter). .dev and other HSTS-preloaded domains don’t affect this — host-key pinning is the SSH layer, independent of TLS.

Non-SSH transport: the stratum agent

By default stratum drives a box over SSH. A host can instead be driven over the stratum agent — a small HTTPS daemon running on the box that executes commands on stratum’s behalf — by setting transport = "agent". This is opt-in per host: every other host keeps SSH, and existing configs are unaffected.

host "box" {
  addr        = "root@192.0.2.10"   # still used to identify the host
  transport   = "agent"
  agent_url   = "https://192.0.2.10"
  agent_token = "STRATUM_AGENT_TOKEN_BOX"          # env var NAME, not the token
  agent_cert_sha256 = "9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08"  # optional
}
  • agent_url — where the agent (or the TLS reverse proxy in front of it) listens. Providers POST /v1/exec here instead of shelling out to ssh.
  • agent_token names an environment variable; stratum reads the bearer token from that variable at connect time. The token value is never written into a host block, resource attrs, state, plan output, or error messages — only the variable name is. Keep the secret in your shell/CI environment (e.g. export STRATUM_AGENT_TOKEN_BOX=...), the same way you’d hold any other credential.
  • agent_cert_sha256 (optional) pins the agent’s TLS certificate by the hex sha256 of its DER encoding. When set, stratum accepts only that exact certificate — the TLS twin of host_key pinning — which is how you use a self-signed or tls internal cert safely. Omit it when the agent is fronted by a public-CA (ACME) certificate, and ordinary hostname + chain verification applies. Capture the pin with openssl s_client -connect <host>:443 </dev/null 2>/dev/null | openssl x509 -outform der | openssl dgst -sha256.

transport = "agent" requires both agent_url and agent_token; either missing is a load-time error. Under the hood the fields lower to reserved _transport / _agent_* attrs, exactly like the _ssh_* connection attrs, so every resource targeting the host inherits the route.

swap

Each host gets an implicit swapfile resource (system_swap) unless suppressed. swap sizes it:

valueeffect
unset4G (the default)
true4G
falsesuppress the implicit swap resource
a number n<n>G
a size stringused verbatim ("2G", "512M")

An invalid size string is a hard error at load time.

Multiple hosts

Declare as many as you need. Each one is independent.

host "prod"    { addr = "root@192.0.2.10" }
host "staging" { addr = "root@5.6.7.8" }

resource "ssh_exec" "uptime_prod" {
  host    = host.prod.addr
  command = "uptime"
}
resource "ssh_exec" "uptime_staging" {
  host    = host.staging.addr
  command = "uptime"
}
